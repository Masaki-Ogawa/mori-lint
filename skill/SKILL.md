# mori-lint（報告前の自己検査）

報告を出す側のエージェントが、報告文を渡す前に自分で検査するための手順です。検査の正はCLI（mori-lint）であり、このスキルの文章だけの手順は、CLIが使えない環境での補助です。

mori-lintは事実かどうかを判定しません。判定するのは「根拠が本文に書かれているか」までです。検査に通ったことは、内容が正しいことの証明にはなりません。

## 手順

1. 報告文をMarkdownファイルに書く（下書きの段階でよい）
2. 文書の種類に合うプリセットを選ぶ
   - 運用報告・定例サマリー: `ops`（必須欄は弱気シナリオ・リスク試算、未確認事項、前提）
   - コード変更の報告・PR説明: `coding`（必須欄は変更内容、検証結果、未確認事項）
   - 調査・比較の報告: `research`（必須欄は出典、未確認事項、反対仮説または弱い点）
   - それ以外: `generic`（必須欄は未確認事項、前提）
3. 検査を実行する

```bash
npx mori-lint report.md --preset ops
```

英語の報告文もそのまま検査できます（言語は自動判定され、検出メッセージも英語で返ります）。

4. 結果への対応
   - **errorは必ず直す**。直せない場合は、報告自体を「未完了」として出し直す
   - **warnは直すか、直さない理由を報告本文に書く**。理由なく放置しない
   - 抑制指定（`<!-- mori-lint-disable MORI001 reason: ... -->`）は、引用など正当な理由がある場合だけ使う。理由のない抑制は警告される
5. 直したら再実行し、errorが0件になってから報告を渡す

## 各ルールで直すこと

- MORI001 絶対表現: 「完全に」「問題ありません」で締めず、留保（検知間隔、対象範囲、残件）を書く
- MORI002 必須欄の欠落: 欄自体を追加する。中身がなければ「なし」と理由を書く
- MORI003 根拠のない「なし」: 確認した方法や根拠を添える
- MORI004 証跡のない完了宣言: URL、ファイルパス、コミット、実行結果など、後から確かめられるものを同じ段落に添える
- MORI005 分母のない全件主張: 「120件中120件」の形で総数と確認済み件数を書く
- MORI006 根拠表示のない数字: 出典か計算式（単価 × 件数 ＝ 合計）を添える
- MORI007 金額・影響のないリスク欄: 起きた場合の影響を金額・件数・時間の数値で書く

## CLIが使えない環境での代替手順

コマンドが実行できない場合は、渡す前に次の7点を目視で確かめる。ただしこれは補助であり、CLIが使える環境ではCLIの結果を正とする。

1. 「完全に」「絶対に」「問題ありません」などの断定が残っていないか
2. 未確認事項と前提の欄があるか
3. 「なし」だけで終わっている欄がないか
4. 完了を述べた段落に証跡があるか
5. 「全件」「すべて」に分母があるか
6. 数字に出典か計算式があるか
7. リスクの欄に影響の数値があるか
